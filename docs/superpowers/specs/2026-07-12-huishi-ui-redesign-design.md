# 绘世全站 UI 优化设计规范

日期：2026-07-12  
状态：待书面确认  
适用范围：主站普通用户页面、画布子应用、后台管理页面

## 1. 背景

绘世当前由两套前端组成：

- Flask 主站：主页、认证、生成工作台、资产、账户、计费与后台管理。
- Next.js 画布子应用：画布项目、无限画布、生图、视频、素材与设置。

本次优化参考电影感视频、液态玻璃和克制动效，但不照搬太空旅行内容，也不改变现有业务结构。品牌表达采用“绘梦造世”，首页继续使用现有视频素材。产品界面以清晰、高密度和长时间使用为优先。

页面设计总览包含 27 个界面：用户端 17 个，管理端 10 个。总览中的结构已与现有模板、React 组件和运行站点对照。

## 2. 目标

1. 统一 Flask 主站、Next.js 画布子应用和后台管理的视觉语言。
2. 提供可切换的瓷白、曜黑和跟随系统主题。
3. 保留每个页面现有的信息架构、交互边界和业务入口。
4. 提升导航、表单、表格、资产卡片、弹窗和状态反馈的一致性。
5. 让首页具备电影感，同时让工作台和管理页面保持安静、耐用和高效。
6. 将后台生成记录和计费流水合并为统一的“业务流水”展示视图。
7. 覆盖真实数据边界：缺图、长提示词、长用户名、加载、失败、空状态和权限状态。

## 3. 非目标

- 不更换首页现有视频素材。
- 不重写生成、计费、认证、资产或画布业务逻辑。
- 不把提示词 iframe 重做成 Flask 自建页面。
- 不改变无限画布的节点、连线、工具栏、缩放、小地图和助手结构。
- 不把生图或视频子应用从三栏改为两栏。
- 不合并生成记录与积分流水的底层数据表；只合并管理端展示与查询入口。
- 不新增未确认的个人设置、云同步或计费能力。

## 4. 设计原则

### 4.1 同一语言，不同密度

- 首页：现有视频、局部液态玻璃、品牌叙事和有限的入场动效。
- 创作工具：紧凑表面、清晰分区、稳定尺寸和状态驱动动效。
- 后台管理：高密度表格、低装饰、明确筛选和可审计状态。

### 4.2 结构优先

UI 优化只改变视觉令牌、组件样式和必要的响应式行为。不得为了参考图效果删除或新增页面栏位。

### 4.3 玻璃按场景使用

液态玻璃仅用于首页导航、首页 CTA、悬浮工具栏、弹窗和需要浮在影像/画布之上的控件。普通内容面板使用明确的实体表面，不将玻璃作为默认卡片样式。

## 5. 视觉系统

### 5.1 字体

产品界面统一使用现代无衬线字体，不使用 Instrument Serif 或书法感中文字体。

```css
--font-ui: "Noto Sans SC", "Microsoft YaHei UI", "PingFang SC", sans-serif;
--font-latin: "Barlow", "Noto Sans SC", sans-serif;
```

- 中文标题、正文、表单、按钮和数据统一使用 `--font-ui`。
- 英文短标签可使用 `--font-latin`，但不得形成第二套视觉层级。
- 产品页采用固定 `rem` 字号，不使用随视口缩放的字体。
- 数据列使用等宽数字特性 `font-variant-numeric: tabular-nums`。

### 5.2 颜色令牌

颜色使用 OKLCH 原始令牌和语义令牌。以下值为设计基准，实施时需通过对比度检查微调。

```css
:root {
  --neutral-0: oklch(100% 0 0);
  --neutral-50: oklch(98% 0.004 250);
  --neutral-100: oklch(95.5% 0.006 250);
  --neutral-200: oklch(91.5% 0.008 250);
  --neutral-600: oklch(53% 0.015 250);
  --neutral-900: oklch(22% 0.008 250);
  --blue-500: oklch(57% 0.24 265);
  --blue-100: oklch(95% 0.035 265);
  --green-600: oklch(52% 0.14 160);
  --red-600: oklch(55% 0.2 25);
}

[data-theme="light"] {
  --color-bg: var(--neutral-50);
  --color-surface: var(--neutral-0);
  --color-surface-subtle: var(--neutral-100);
  --color-border: var(--neutral-200);
  --color-text: var(--neutral-900);
  --color-text-muted: var(--neutral-600);
  --color-primary: var(--blue-500);
  --color-primary-soft: var(--blue-100);
}

[data-theme="dark"] {
  --color-bg: oklch(15% 0.006 250);
  --color-surface: oklch(20% 0.008 250);
  --color-surface-subtle: oklch(25% 0.01 250);
  --color-border: oklch(30% 0.012 250);
  --color-text: oklch(96% 0.003 250);
  --color-text-muted: oklch(72% 0.012 250);
  --color-primary: oklch(70% 0.15 265);
  --color-primary-soft: oklch(27% 0.07 265);
}
```

- 钴蓝只用于主要操作、焦点、当前导航和选中状态。
- 成功、警告、错误颜色只表达语义，不作装饰。
- 浅色主题不用灰绿或暖米色背景。
- 深色主题通过表面亮度建立层级，不使用大面积阴影。

### 5.3 圆角、边框与阴影

```css
--radius-control: 6px;
--radius-panel: 8px;
--radius-dialog: 10px;
--radius-pill: 9999px;
--border-default: 1px solid var(--color-border);
--shadow-float-light: 0 4px 12px rgb(16 24 40 / 6%);
```

- 卡片和页面面板不得超过 12px 圆角。
- 标签、切换组和短按钮可使用胶囊圆角。
- 实体面板不同时叠加强边框和大面积柔影。

### 5.4 图标

- Flask 主站沿用现有 SVG 图标体系并统一为 1.75-2px 描边。
- Next.js 画布优先使用 `lucide-react` 或现有 Ant Design 图标。
- 图标按钮必须有 `aria-label` 和悬停提示。

## 6. 主题架构

主题值为 `system | light | dark`。

- Flask 主站由 `static/js/theme.js` 管理，保存小型偏好值。
- Next.js 画布由现有 `useThemeStore`、`canvasThemes` 和 Ant Design `ConfigProvider` 管理。
- 主站嵌入画布时，复用既有 iframe ready/ping 桥接，并增加主题消息。
- 主题消息格式固定为 `{ type: "huishi-theme-change", preference: "system" | "light" | "dark", resolvedTheme: "light" | "dark" }`。
- 主站只向配置的画布 iframe `contentWindow` 发送消息，并使用从 `HUISHI_CANVAS_APP_URL` 解析出的明确 `targetOrigin`，不得使用 `"*"`。
- 画布只接受来自父窗口且来源匹配主站 origin 的主题消息；消息字段不符合契约时忽略。
- iframe ready 后主站立即发送当前主题；主题或系统配色变化时再次发送。
- iframe 初始化时读取主站传入主题；独立打开画布时读取画布自身偏好。
- 系统主题变化时，`system` 模式应即时同步。
- 切换主题只改变语义令牌，不改变页面结构和尺寸。

Flask 和 Next.js 分别维护本地令牌映射，不在本次改造中新增跨项目共享包。两端语义名称和设计值以本规范为契约。

## 7. 页面结构

### 7.1 品牌与认证（4）

1. 首页：现有视频、顶部导航、Hero、能力区；登录/注册使用模态框。
2. 登录/注册：保留首页模态框边界，覆盖提交中和错误状态。
3. 重置密码：独立品牌入口和验证码/新密码表单。
4. 邮箱验证：验证码输入、重发、过期和返回工作台。

首页不增加全局遮罩。视频亮部影响可读性时，使用局部玻璃承托、文字落点调整或文字阴影，不更换素材。

### 7.2 Flask 主站创作（4）

1. 生成工作台：窄全局工具栏、对话历史侧栏、中央结果流、底部固定输入区。
2. 图片资产库：保留窄工具栏与对话侧栏，使用搜索、时间、筛选、批量操作和资产网格。
3. 资产详情：全屏媒体区加右侧详情面板，不显示工作台左侧工具栏。
4. 提示词入口：主站壳加画布应用 iframe，不复制提示词库实现。

### 7.3 Next.js 画布子应用（6）

1. 画布项目列表：顶部工具导航、项目网格、新建和批量删除。
2. 无限画布编辑器：保留节点、连线、底部工具栏、缩放、小地图和助手面板。
3. 生图工作台：生成记录、可滚动参数、生成结果三栏。
4. 视频创作台：生成记录、多媒体参数、生成结果三栏。
5. 我的素材：本地图片、视频、音频筛选和上传。
6. 画布设置：只呈现现有 API、主题、存储和连接相关配置。

### 7.4 账户与计费（3）

1. 账户中心：顶部导航、余额、API 模式、邀请码和积分流水。
2. API Key：顶部导航、Key 设置和清除危险区。
3. 积分说明：顶部导航、当前余额、分辨率规则和套餐说明。

以上页面不添加工作台左侧工具栏。

### 7.5 管理端运营（4）

1. 运行总览：指标、服务健康和最近业务。
2. 用户管理：筛选、批量操作、横向可滚动表格和编辑抽屉。
3. 用户业务流水：统一业务流水按用户预筛选，并提供余额调整。
4. 全站业务流水：生成、扣费、奖励、调整、退款和失败事件统一展示。

管理端侧栏、顶栏和内容区跟随同一主题，不使用固定黑色侧栏。

### 7.6 管理端计费与系统（6）

1. 邀请码管理。
2. 计费规则。
3. 套餐管理。
4. 配置中心。
5. 系统配置。
6. 审计日志。

## 8. 统一业务流水

“记录与流水”导航改为“业务流水”。

统一表格字段：

- 时间
- 用户
- 事件类型
- 业务详情
- 积分变化
- 状态
- 关联记录
- 操作

事件类型包括：图像生成、参考图编辑、视频生成、邀请码奖励、管理员调整、退款和失败。

生成事件显示提示词摘要、模式、分辨率、尺寸和模型。点击“查看”打开详情抽屉，展示完整提示词、参数、耗时和关联计费流水。

底层生成记录和积分流水仍分别存储，通过 `record_id` 等现有关联字段组合查询。不得为了 UI 合并破坏审计边界或交易一致性。

后台为列表页提供规范化的只读事件 DTO，不做数据库迁移：

```text
id, occurred_at, user_id, username, event_type, summary,
mode, resolution, actual_size, model_source,
points_delta, status, record_id, ledger_id, actor, note
```

- 生成事件优先以生成记录为主记录，并关联对应计费流水。
- 奖励、管理员调整和退款等无生成记录事件以积分流水为主记录。
- 列表分页、用户、事件类型、模式、状态、日期和关键词筛选在服务端完成。
- 同一底层事件不得重复显示；DTO 组合规则需要独立测试一对一、无记录流水和失败退款场景。

## 9. 组件契约

全站需要统一以下组件的视觉和状态：

- `AppShell`：全局导航、侧栏、顶栏和主内容。
- `Button`：primary、secondary、quiet、danger、icon。
- `FormControl`：input、textarea、select、checkbox、switch、stepper。
- `Tabs` 与 `SegmentedControl`。
- `DataTable`：固定表头、横向滚动、截断和操作列。
- `AssetTile`：媒体、标题、元数据、状态和批量选择。
- `Dialog`、`Drawer`、`Popover`、`Tooltip`。
- `StatusBadge`：success、warning、error、neutral、loading。
- `EmptyState`、`Skeleton`、`ErrorState`。

每个交互组件必须覆盖 default、hover、focus-visible、active、disabled、loading 和 error。

## 10. 数据边界与错误处理

- 缺图：显示明确占位、资源状态和可重试/查看详情入口，不只显示破损图片图标。
- 超长提示词：网格卡片单行截断并提供完整标题；详情页允许多行阅读。
- 长用户名和时间戳：表格截断加 tooltip；时间提供可读格式并保留机器值。
- 大表格：限定表格容器横向滚动，页面壳本身不得横向溢出。
- iframe：覆盖加载、配置缺失、超时、拒绝访问和重试。
- 生成任务：覆盖排队、运行、成功、失败、退款和取消。
- 权限：无权限操作不渲染或明确禁用，不能只依赖颜色区分。

## 11. 动效

- 首页可使用一次性入场、文字淡入和现有视频 rAF 淡入淡出。
- 产品页动效为 150-250ms，只表达状态变化。
- 画布节点拖拽、连接和助手面板沿用现有 Motion 逻辑。
- 禁止产品页统一编排式入场动画。
- `prefers-reduced-motion: reduce` 时取消位移和模糊，只保留即时切换或短淡入。

## 12. 响应式行为

- 首页：320px 起可用；导航折叠，Hero 文案不溢出，下一屏有可见提示。
- 工作台：窄屏折叠对话历史，但保留全局工具入口和输入区。
- 资产库：网格自适应，筛选进入抽屉，批量栏固定且不遮挡内容。
- 三栏生图/视频：中等宽度压缩栏宽；移动端按记录、参数、结果分段切换，不将三栏硬挤在同屏。
- 后台表格：侧栏可收起，表格容器内部横向滚动，操作列保持可达。
- 画布编辑器：使用现有移动工具栏与面板布局。

## 13. 可访问性

- 普通文字对比度至少 4.5:1，大文字和 UI 边界至少 3:1。
- 所有点击目标移动端至少 44x44px。
- 主题切换、标签页、弹窗和抽屉具备键盘操作和正确 ARIA。
- 焦点环使用主色，不能被 `overflow` 裁切。
- 不禁用浏览器缩放，200% 缩放仍能完成核心任务。

## 14. 测试与验证

### 自动检查

- Flask 测试和现有首页资源预算测试。
- `npm run verify:home`。
- 编码检查和静态资源预算检查。

画布子项目的 `bun test`、`bun run typecheck` 和 `bun run build` 由用户运行，或在用户明确授权后运行，以遵守 `infinite-canvas/AGENTS.md` 的验证约束。Codex 在未获授权时只做源码级和浏览器级检查，并明确报告未执行的命令。

### 浏览器验证

至少检查：

- 桌面：1440x900、1280x720。
- 平板：768x1024。
- 移动：390x844、320x568。
- 瓷白、曜黑、跟随系统。
- 首页视频、登录模态框、工作台、资产库、资产详情、iframe、画布、生图、视频、账户、业务流水和用户表格。
- 控制台错误、资源 404、布局溢出和焦点可见性。

## 15. 实施顺序

1. 建立主题和组件令牌，统一字体、颜色、圆角和焦点状态。
2. 优化首页和认证模态框，保留现有视频和 rAF 视频逻辑。
3. 优化 Flask 工作台、资产库、资产详情和提示词 iframe 壳。
4. 优化账户、API Key、积分和认证辅助页面。
5. 同步 Next.js 画布应用主题与通用组件，不改变画布结构。
6. 优化生图、视频、素材和画布设置页面。
7. 优化后台并实现统一业务流水展示。
8. 完成全页面视觉回归、响应式检查和可访问性检查。

## 16. 验收标准

- 27 个页面均使用同一语义令牌体系。
- 主题切换在主站、iframe 和独立画布中一致工作并保持偏好。
- 不存在旧灰绿浅色背景、固定黑色管理侧栏或产品页衬线斜体标题。
- 工作台、资产、画布、生图、视频、账户和后台结构与现有功能保持一致。
- 业务流水可在一个界面查询生成与积分事件，并保留关联详情。
- 缺图、长文本、空状态、加载、失败、权限和退款状态有明确设计。
- 320px 至桌面宽度无非预期页面级横向溢出。
- 自动测试、构建和浏览器验证通过，无新增严重控制台错误。
