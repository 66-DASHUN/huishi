# Grok 与新增生图模型配置设计

## 目标与范围

本次改动覆盖四个相互关联的后台能力：

1. 优化 Grok 模型配置与前端选择。
2. 补齐 Grok Imagine 2.0、Nano Banana 2、Nano Banana Pro 的接口配置。
3. 将生图模型价格规则从渠道表单中分离，支持按模型和分辨率维护。
4. 在管理后台增加安全的“新增用户”能力，并整理现有系统配置布局。

不改变现有 OpenAI 兼容渠道的调用行为，不删除已有 API Key、Base URL、优先级、启用状态或用户资源。

## 模型目录与显示名称

后端维护协议驱动的模型目录，每个条目包含真实模型 ID、显示名称、默认 Base URL、接口协议、支持分辨率和默认模型标记。前端只显示显示名称，提交时使用真实模型 ID。

### Grok

- 显示名称：`grok-imagine 2.0`
- 调用 ID：`grok-imagine-image-2.0`
- 协议：Grok 官方
- 默认 Base URL：`https://api.x.ai/v1`
- 支持分辨率：`1K`、`2K`
- 生图接口：`/v1/images/generations`
- 参考图编辑接口：`/v1/images/edits`
- 默认模型：是

旧 ID `grok-imagine-image` 和 `grok-imagine-image-pro` 不再出现在模型选项中。数据库兼容迁移会把它们迁移到 `grok-imagine-image-2.0`，保留连接和运营字段；若迁移后出现重复渠道或价格规则，则按确定的合并规则去重。

### Nano Banana

- `Nano Banana 2` → `gemini-3.1-flash-image`
- `Nano Banana Pro` → `gemini-3-pro-image`
- 协议：Nano Banana（Gemini 官方）
- 默认 Base URL：`https://generativelanguage.googleapis.com`
- 支持分辨率：`1K`、`2K`、`4K`
- 接口：`/v1beta/interactions`

“自定义模型 ID”作为显式备用入口保留。开启后允许兼容网关或未来模型使用任意模型 ID，但仍由后端根据所选协议执行基础校验。

## 配置页信息架构

系统配置页按业务分区展示：

- 生图渠道
- 提示词服务
- 系统参数
- 计费规则

生图渠道使用简约表格，每行一个渠道配置，新增和编辑使用同一套紧凑表单。字段分三组：

1. 常用字段：名称、调用协议、模型、启用状态。
2. 连接字段：Base URL、API Key。API Key 默认掩码；编辑其他字段不会清空已保存 Key，只有明确更新操作才替换。
3. 能力字段：支持分辨率、优先级，以及模型能力提示。

模型选择器显示友好名称，并在旁边显示只读的真实 ID。自定义模型 ID 输入默认折叠，打开开关后才展示。切换协议或模型时，若 Base URL 和分辨率字段为空，自动填入官方默认值；已有自定义网关配置不被覆盖，并提供“恢复默认”操作。

桌面端使用紧凑双列布局，窄屏自动单列；保留现有“管理后台”入口、权限、CSRF、审计和删除确认行为。

## 调用与校验

保存渠道时，后端规范化协议、模型 ID 和分辨率，并验证协议与模型匹配。Grok 的 4K 选项在前端禁用，后端再次拒绝非法请求；Nano Banana 允许 1K、2K、4K；OpenAI 兼容渠道沿用现有行为。

生成请求按协议路由：

- Grok：`/v1/images/generations` 或 `/v1/images/edits`。
- Nano Banana：`/v1beta/interactions`。
- OpenAI 兼容：现有生图和编辑路径。

错误信息包含渠道、模型和分辨率，避免把 API Key 或完整敏感 URL 写入日志；单个渠道失败不改变其他已启用渠道。

## 计费规则

价格规则独立显示为“模型 × 分辨率 × 单张价格”表格，支持新增、编辑、启用/停用。新增并初始化以下模型的独立价格记录：

- `grok-imagine-image-2.0`
- `gemini-3.1-flash-image`
- `gemini-3-pro-image`

各模型的 1K、2K、4K 价格可分别配置；Grok 的 4K 记录默认停用或不生成。原 Grok 价格规则迁移到 2.0，若目标规则已有明确人工配置，以目标配置为准，避免重复扣费。

## 管理员新增用户

管理后台增加用户管理表格和“新增用户”按钮。表单字段为用户名或邮箱、初始密码、角色（普通用户/管理员）、启用状态和初始积分。

服务端校验用户名/邮箱唯一性、密码强度、角色枚举和积分格式；密码使用现有安全哈希机制保存，页面不回显密码。只有管理员能访问新增、编辑和禁用用户接口；普通用户收到拒绝响应。创建成功后用户可直接登录，角色与初始积分立即生效。

## 迁移与安全

应用启动或数据库初始化时执行幂等兼容迁移：

1. 备份数据库。
2. 将旧 Grok 模型 ID 更新为 `grok-imagine-image-2.0`。
3. 合并重复渠道和价格规则，优先保留目标记录的明确人工配置。
4. 将分辨率裁剪为模型支持集合。
5. 记录迁移结果，失败时回滚本次事务并保持服务可启动。

迁移不删除图片资源、不重置 API Key、不改变其他渠道。自定义模型 ID 不参与旧 Grok 自动迁移，只有明确匹配旧 ID 的记录才处理。

## 验收与测试

- Grok 选项只有 `grok-imagine 2.0`，提交值为 `grok-imagine-image-2.0`。
- Nano Banana 两个模型显示名称与真实 ID 正确对应。
- 自定义模型 ID 可保存并可正常调用。
- 协议切换能填充默认 Base URL，不覆盖自定义值。
- Grok 只能保存/提交 1K、2K；Banana 可保存/提交 1K、2K、4K。
- Grok generations、edits 和 Banana interactions 请求路径、请求体和响应解析通过测试。
- 旧 Grok ID 迁移幂等，重复执行不会重复创建渠道或价格规则。
- 每个新增模型均有独立价格规则，扣费按模型和分辨率匹配。
- 管理员可新增用户，普通用户不能调用管理接口；密码不以明文落库或回显。
- 系统配置页在桌面和窄屏下布局稳定，API Key 编辑行为、CSRF 和现有管理入口不回归。
