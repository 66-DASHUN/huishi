# 绘世完整项目优化设计

## 目标

在保留 Flask、PostgreSQL、Redis/RQ、Next.js 与现有画布能力的前提下，把绘世交付为可备份、可回滚、可运营、可审计、桌面与移动端可用的完整项目。

## 已确认现状

- Nginx 提供 `huishi.local` 与 `canvas.huishi.local` 两个 HTTPS 入口。
- Flask/Gunicorn、PostgreSQL、Redis、4 个 RQ worker、Next.js 画布和 Canvas Agent 正在运行。
- 画布 TypeScript 类型检查通过；后端全量测试未在运行中的 VM 上执行，避免测试误写生产数据库或文件。
- `/opt/huishi` 没有 Git 元数据，现有恢复材料只有两份 SQL 和两份代码压缩包。
- 根分区 14 GB，当前使用率 74%。
- `/opt/huishi` 与 Canvas Agent 目录权限为 `777`；Canvas Agent 以个人账号和个人 HOME 运行。
- 管理后台具备用户、积分、邀请码、套餐、计费、Provider、SMTP 与记录管理，但没有管理员操作审计、配置版本、搜索分页与运行健康视图。
- 390px 画布编辑器中，底部工具栏内容超出视口；桌面画布主要流程可用。
- 画布域缺少主站已有的通用安全响应头。
- API Key、SMTP 密码与 Agent Token 支持 Fernet 加密；应用代码在 `HUISHI_ENV=production` 时会拒绝缺失或无效的 `HUISHI_ENCRYPTION_KEY`，但当前账号无权读取线上环境文件来留存非敏感配置证据。

## 范围与顺序

### 阶段 1：运维安全基线

1. 建立每日 PostgreSQL 备份、校验和、保留策略与恢复命令。
2. 建立部署前代码快照和可重复的回滚流程。
3. 将应用代码改为 root 拥有、运行账号只读；仅上传、缓存、日志与备份目录允许运行账号写入。
4. Canvas Agent 使用专用低权账号、独立 HOME，并启用 systemd 沙箱选项。
5. 为现有生产密钥强制校验补齐回归测试，并在部署证据中只记录配置键存在性，不输出值。
6. 为画布域补齐安全响应头并隐藏 `X-Powered-By`。
7. 将正常的 `SIGTERM` 停止识别为成功退出，避免部署重启污染故障统计。

### 阶段 2：管理控制台

1. 新增管理员操作审计表，覆盖积分、密码、角色、用户删除、批量导入、邀请码、套餐、计费、Provider、SMTP 与 Agent 配置变更。
2. 审计记录保存操作者、动作、对象、结果、请求标识、必要的脱敏前后值和时间；任何密钥、密码、Token 不进入审计正文。
3. 管理首页增加服务、队列、失败任务、Provider、磁盘、备份和存储清理状态。
4. 用户、邀请码、生成记录和积分流水改为服务端分页、搜索与筛选。
5. 保留现有 `admin` 兼容行为，同时新增 `super_admin`、`operator`、`support`、`viewer` 四个角色；权限在后端统一判断，前端只负责隐藏无权入口。
6. 高风险操作使用明确的二次确认和必填原因；查看操作使用低摩擦交互。

## 管理后台视觉与交互

- 采用安静、密集、面向重复操作的运营控制台，而不是营销式卡片页面。
- 桌面端为左侧一级导航、顶部运行状态、主内容表格与右侧详情抽屉。
- 运行状态仅显示服务健康、队列、失败率、磁盘和备份等可行动指标。
- 列表页统一使用搜索、状态筛选、时间范围、分页和导出；批量操作在选中数据后才出现。
- 危险操作与普通编辑分区，删除、提权、改密和大额积分调整必须展示影响对象。
- 移动端管理页只保证查看、搜索和单条处理；批量导入与复杂配置明确引导到桌面端。

### 阶段 3：移动画布与用户体验

1. 390px 宽度下固定展示“选择、文字、图片、上传、更多”五个高频入口。
2. 撤销、重做、视频、音频、生成配置、素材库、画布外观、快捷键与清空操作进入“更多工具”面板。
3. 桌面端保留当前完整工具栏，不改变成熟用户的肌肉记忆。
4. Agent 面板在窄屏使用全宽抽屉，关闭后完整归还画布空间。
5. 节点设置面板使用视口约束，避免 500px 固定宽度溢出移动端。
6. 补齐会话校验、项目加载、上传、生成、失败、空画布和离线状态。
7. 画布列表、编辑器和素材选择器均验证 390x844、768x1024、1280x720 与 1440x900。

### 阶段 4：性能与可维护性

1. 首页只加载首页需要的 CSS；清理未使用的 15.5 MB 旧视频并保留经过压缩的首屏媒体。
2. 对首页和画布执行 bundle 分析，将编辑器、Prompt 库、Agent、视频与音频功能按需加载。
3. 渐进拆分 3503 行的 `canvas-client-page.tsx`，优先提取移动工具栏、画布视口、Agent 生命周期与素材插入逻辑；每次拆分保持行为不变。
4. 补齐根项目实际可运行的 `npm test`、`npm run check:encoding` 与统一验证入口。
5. 建立部署前验证、部署后 smoke、运行健康和回滚检查表。

## 数据模型

新增 `admin_audit_logs`：

- `id`
- `actor_user_id`
- `action`
- `target_type`
- `target_id`
- `summary`
- `before_json`
- `after_json`
- `result`
- `request_id`
- `created_at`

`before_json` 与 `after_json` 只允许预定义字段，并经过统一脱敏。审计表只追加，不提供后台删除入口。

用户角色扩展为 `admin`、`super_admin`、`operator`、`support`、`viewer`、`user`。现有 `admin` 在过渡期映射到全部管理权限，待首个 `super_admin` 验证后再收紧。

## 组件边界

- `huishi/admin_audit.py`：审计写入、脱敏与查询。
- `huishi/admin_permissions.py`：角色与权限映射、装饰器和模板能力判断。
- `huishi/operations.py`：只读运行健康采集。
- `huishi/routes_admin.py`：保留 HTTP 参数解析与页面响应，业务逻辑下沉到上述模块。
- `templates/admin/`：共享后台壳、导航、状态条、列表工具栏和分页。
- `static/js/admin.js`：抽屉、筛选与确认交互，不保存业务状态。
- `canvas-mobile-toolbar.tsx`：移动端主工具和更多工具面板。
- `use-canvas-viewport.ts`：画布视口和窄屏布局状态。
- `use-canvas-agent-lifecycle.ts`：Agent 打开、关闭、宽度与移动抽屉行为。

## 错误处理

- 备份失败必须返回非零状态并写入 journal；健康页显示最近一次成功、最近一次失败与文件大小。
- 健康采集采用短超时，单个依赖失败不阻断后台页面渲染。
- 管理写操作失败也写审计记录，但不记录用户密码、API Key、SMTP 密码或 Token。
- 前端请求失败展示可恢复操作；重复提交按钮在请求期间禁用。
- 移动画布更多工具面板关闭后恢复焦点到触发按钮。

## 发布与回滚

1. 每个阶段发布前执行数据库备份和代码快照。
2. 数据库变更使用向前兼容的新增表/新增角色值，不在同一发布删除旧字段。
3. 先部署代码与表，再启用新导航和权限；旧 `admin` 在过渡期保持可用。
4. 前端构建在临时目录完成，通过后原子切换构建产物。
5. smoke 失败时恢复上一代码快照并重启对应服务；新增审计表可保留，不影响旧代码。

## 测试策略

- 后端：每项新行为先写失败测试，再实现；测试使用临时 SQLite 和独立 PostgreSQL 测试库，不连接运行库。
- 管理权限：对每个角色建立允许/拒绝矩阵测试。
- 审计：验证成功、失败、批量操作和敏感值脱敏。
- 前端：类型检查、组件行为测试、构建和浏览器流程。
- 视觉：桌面与移动截图检查文字、溢出、焦点、加载/空白/错误状态。
- 运维：备份、校验、恢复到临时数据库、服务 smoke 与回滚演练。

## 验收标准

- 备份每天自动执行，有校验和、保留策略和一次真实恢复证据。
- 代码和数据均有可执行回滚路径；敏感文件不进入代码快照。
- 应用账号不能修改应用源码，Agent 不能读取个人 HOME。
- 画布域具备 HSTS、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`，且不暴露 `X-Powered-By`。
- 所有高风险管理操作可按操作者、对象、动作和时间查询，日志不含敏感值。
- 管理列表不再全量加载；搜索、筛选和分页在数据量增长后仍可用。
- 390px 画布没有不可达工具，节点面板和 Agent 不超出视口。
- Flask 与 Next.js 保持现有技术栈，核心生成、计费、资产、画布和管理员流程全部通过回归验证。

## 非目标

- 不更换 Flask、Next.js、PostgreSQL、Redis/RQ。
- 不在本轮建设多机高可用或对象存储迁移。
- 不一次性重写画布编辑器。
- 不在没有独立测试数据库的运行 VM 上执行可能写数据的全量测试。
