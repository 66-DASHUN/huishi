# 双工作页面媒体生成能力设计

## 目标与边界

本次改动将图片生成、视频生成、语音合成和音乐生成分别加入两个已有工作页面：

1. 旧版创作功能页 `/workspace`。
2. React 无限画布页 `/canvas`。

两个页面保持独立的布局、交互和状态管理，不合并为一个统一工作台，也不把画布节点改造成旧版功能页。两页只共享渠道、模型目录、能力标识、参数定义、计费信息和后端媒体生成适配器。

不改变无关的对话、历史记录、画布连线、用户权限和已有资源目录行为。部署时保留线上 `.env`、数据库、Redis 和 `data/uploads`，只重启实际变更的服务。

## 共享领域模型

### 媒体能力

后端和前端统一使用以下能力标识：

```text
image | video | speech | music | prompt
```

旧配置中的 `audioModel` 和 `audioModels` 继续读取，但迁移后作为 `speechModel` 和 `speechModels` 的兼容初始值。新配置增加：

```text
speechModel
speechModels
musicModel
musicModels
```

每个模型目录项至少包含：

- `id`：实际调用模型 ID
- `displayName`：界面显示名称
- `provider`：渠道或协议
- `capabilities`：支持的能力列表
- `defaults`：默认参数
- `pricing`：计费信息
- `enabled`：是否允许用户选择

同一个渠道可以包含多个模型；用户选择的是模型目录项，后端根据模型所属协议和能力路由到对应适配器。模型列表不能只依赖单一渠道的 `/models` 响应，官方固定目录、兼容网关返回列表和管理员手动添加的模型都可以并存，并标记来源。

### 渠道与连接配置

管理员为每个渠道维护：

- 名称、协议和 Base URL
- API Key 或等效凭据（读取时始终掩码）
- HTTP/SOCKS 代理及超时
- 支持的能力
- 可用模型列表
- 模型级价格和启用状态

OpenAI 兼容、Grok、Gemini/Nano Banana、MiniMax、Seedance、即梦、H3 等协议使用独立适配器；一个渠道故障不得阻断其他渠道。连接测试和生成测试都必须使用当前渠道自己的 Base URL、代理、Key 和模型。

## 页面一：旧版创作功能页 `/workspace`

### 入口与布局

保持现有提示词输入区、历史记录、对话侧栏和结果流。底部生成区增加并列的模式选择：

```text
图片生成 | 视频生成 | 语音合成 | 音乐生成
```

模式切换不会跳转页面，也不会改变历史记录的已有结构。当前模式需要在视觉上明确，模型下拉框只显示该能力可用的模型。

### 参数隔离

- 图片：提示词、参考图片、尺寸/比例、质量、数量、种子等现有图片参数。
- 视频：提示词、首帧/尾帧或参考视频、比例、时长、分辨率、运动强度等模型支持的参数。
- 语音合成：文本、声音、语速、音量、音调、情绪、语言、采样率、格式等 MiniMax T2A 参数。
- 音乐生成：描述、歌词、纯音乐开关、歌词优化、参考音频、音频格式等 MiniMax 音乐参数。

切换模式时清理或隐藏不适用的参数，不能把图片数量、视频时长或音乐歌词提交到其他能力。默认生成数量为 1；仅在当前模型支持批量生成时显示已有数量选项。

### 结果与错误

图片沿用现有图片卡片。视频、语音和音乐使用对应的媒体结果卡片，显示任务状态、预览/播放、下载和重试。音频结果的 metadata 包含 `audioKind: speech|music`。异步任务需要显示排队、生成中、成功、失败和可重试状态；错误信息包含能力、渠道和模型，但不暴露 Key 或完整敏感地址。

## 页面二：React 无限画布 `/canvas`

### 生成配置节点

保留节点、连线、自由拖拽和画布状态。生成配置节点的模式选择改为：

```text
文本 | 图片 | 视频 | 语音合成 | 音乐生成
```

`文本` 继续表示原有提示词/对话工作流，已有 `audio` 模式按语音合成兼容。节点切换模式后只渲染相应模型选择器、参数面板、参考素材和生成按钮；节点可以独立选择模型，不受其他节点选择影响。

### 节点输出

- 图片输出图片节点。
- 视频输出视频节点。
- 语音合成输出音频节点，metadata 为 `audioKind: speech`。
- 音乐生成输出音频节点，metadata 为 `audioKind: music`。

生成节点保存 `capability`、`modelId`、参数快照和资源引用，画布重新打开后能恢复选择，不因后台默认模型变化而改写历史节点。

### 兼容性

旧画布中的 `audio` 节点迁移为 `speech`，保留原参数和连接。无法识别的旧模型保留其 ID 并显示不可用提示，管理员重新启用模型后无需修改节点数据。

## 后端 API 与适配器

### 统一分发

新增或扩展媒体生成分发逻辑，使请求至少携带：

```json
{
  "capability": "image|video|speech|music",
  "model": "model-id",
  "prompt": "...",
  "parameters": {},
  "channelId": "optional"
}
```

服务端根据 `capability + model + channel` 校验参数并选择适配器，不允许客户端直接指定任意 URL 或绕过模型能力校验。现有图片接口保持兼容，新增视频、语音和音乐的异步任务/结果存储路径复用项目现有任务队列和资源目录。

### MiniMax 音频

语音合成适配 MiniMax `POST /v1/t2a_v2`，支持 `speech-2.8-hd`、`speech-2.8-turbo`、`speech-2.6-hd`、`speech-2.6-turbo`、`speech-02-*` 和 `speech-01-*`。默认请求使用非流式 MP3，兼容 hex 音频返回并解码后保存为资源。

音乐生成适配 MiniMax `POST /v1/music_generation`，支持 `music-3.0`、`music-2.6`、`music-cover` 及其兼容目录项。仅 `music-cover` 显示参考音频字段。因官方对新用户的付费/免费音乐接口开放状态有限，管理员和用户看到明确的“接口未开放或无权限”错误，而不是无限重试。

### 连接和模型测试

管理员点击连接测试后弹出小窗，先选择能力，再选择该渠道已配置或从渠道获取到的模型：

- 对话模型执行最小对话请求并显示文本结果。
- 图片模型执行最小生图请求并返回可预览图片。
- 视频模型创建最小视频任务，轮询完成后返回可播放视频或明确失败原因。
- 语音模型合成短文本并返回可播放音频。
- 音乐模型生成最短合法片段并返回可播放音频。

测试请求必须显示进行中状态，处理网络超时、代理失败、模型列表接口不支持和异步任务失败；不能出现点击后无反馈。获取模型列表失败时保留官方目录和已保存模型，并显示可操作的错误原因。

## 管理员配置页

系统配置页按业务分区整理为简约表格：

1. 渠道与连接
2. 模型目录
3. 模型能力与定价
4. 系统默认值

渠道表格每行显示名称、协议、能力、模型数、启用状态和操作。新增/编辑使用紧凑弹窗或侧栏，API Key 默认掩码，编辑其他字段不能清空已保存 Key。模型表格每行显示友好名称、真实 ID、能力、渠道、价格和启用状态，支持先获取模型再勾选添加，也支持明确开启后的自定义模型 ID。

图片、视频、语音和音乐的定价独立按“模型 × 规格 × 单次价格”维护；前端和画布只显示启用且有可用渠道的模型。保留“管理后台”入口、权限、CSRF、审计和删除确认行为。

## 数据迁移与部署

- 启动时将 `audioModel/audioModels` 复制到 `speechModel/speechModels`，仅在新字段为空时执行，幂等且不覆盖管理员已有新配置。
- 为已有渠道补充 `capabilities` 时根据协议和历史模型推断，无法推断的模型保持禁用并提示管理员。
- 不删除旧模型 ID、历史任务或资源；旧 ID 通过兼容映射继续可读。
- 部署前备份线上构建、配置和数据库变更记录；不覆盖 `.env`，不删除或迁移 `/opt/huishi/data/uploads`。
- 只构建并重启实际变更的 backend、workspace 或 canvas 服务，PostgreSQL、Redis、canvas-agent 和无关 worker 不重启。

## 验收标准

- `/workspace` 和 `/canvas` 仍是两个独立页面，任何页面都没有把另一个页面的布局嵌入进来。
- 两页都能选择图片、视频、语音合成和音乐生成，且模型列表按能力过滤。
- 图片默认生成 1 张；旧画布保存的生成数量可以正常编辑。
- 不适用的参数不会出现在请求或界面中；语音与音乐参数完全分离。
- 语音和音乐都能返回可播放音频，视频测试能返回可播放视频或明确的异步失败原因。
- 连接测试弹窗有即时反馈，能按能力选择模型；模型列表获取失败时不会清空已有模型。
- 旧 `audio` 画布节点、历史资源、Key、Base URL 和价格规则不丢失。
- 管理员配置页使用简约表格，模型、渠道和价格可独立增删改停用。
- 本地单元/API/前端测试通过，并在部署后验证两个页面、四类生成和现有服务健康状态。
