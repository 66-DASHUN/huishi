# 绘世系统承载能力与服务器升级预算评估

生成日期：2026-06-18  
评估对象：现有绘世 AI 生图系统  
当前服务器：阿里云 2核2G / 200M  
当前架构：Flask + SQLite + 本地图片存储 + 后台线程池生图队列

## 1. 汇报结论

当前系统可以支撑内测和早期小规模商业化，但不建议直接承接大规模用户。主要原因不是 CPU 不够，而是现有架构使用 SQLite、本地图片存储、进程内线程池队列，系统扩展能力有限。

现阶段建议：

| 阶段 | 推荐配置 | 同时生图任务 | 稳妥日生成量 | 可支撑 DAU | 月服务器预算 |
|---|---:|---:|---:|---:|---:|
| 当前内测 | 2核2G / 200M | 3-5 | 1,000-3,000 张 | 100-800 | 50-150 元 |
| 小规模商用 | 4核8G | 8-15 | 5,000-10,000 张 | 500-3,000 | 200-500 元 |
| 增长期 | 8核16G + OSS | 20-40 | 15,000-30,000 张 | 2,000-10,000 | 600-1,500 元 |
| 中等规模 | 16核32G + OSS + RDS + Redis | 50-100 | 50,000-100,000 张 | 8,000-30,000 | 2,000-6,000 元 |

以上为预算估算，最终价格以阿里云控制台实际报价、地域、计费方式和活动折扣为准。

## 2. 当前系统承载模型

### 2.1 生图任务模型

系统中“一个任务”按用户每次点击生成计算，不按单张图计算。

示例：

```text
用户提交一次 count=4
= 1 个 generation_task
= 上游一次生成 4 张图
= 最终生成 4 条图片记录
```

当前已经新增单用户活跃任务限制：

```env
HUISHI_MAX_ACTIVE_GENERATION_TASKS_PER_USER=2
```

含义：单个用户最多同时有 2 次提交处于 queued/running 状态。这样可以防止一个用户连续点击，把全站队列占满。

### 2.2 生图吞吐公式

根据本地运行日志，2K 单张生图样本约 60 秒完成。实际生产中会受上游 API、网络、图片大小和失败重试影响，因此本报告按 60 秒/任务估算，并按理论吞吐的 50%-70% 作为稳妥规划值。

公式：

```text
理论日生成量 = 同时生图任务数 * 86400 / 平均生成秒数
稳妥日生成量 = 理论日生成量 * 50%-70%
```

### 2.3 DAU 换算口径

DAU 取决于人均每日生成张数：

| 用户类型 | 人均生成量 |
|---|---:|
| 轻度体验用户 | 3 张/日 |
| 普通创作者 | 10 张/日 |
| 重度用户 | 30 张/日 |

因此，同样 3,000 张/日：

- 如果人均 3 张，可支撑约 1,000 DAU。
- 如果人均 10 张，可支撑约 300 DAU。
- 如果人均 30 张，可支撑约 100 DAU。

## 3. 当前 2核2G 服务器评估

### 3.1 推荐配置

当前 2核2G 服务器建议：

```env
HUISHI_GENERATION_WORKERS=3
HUISHI_MAX_GENERATION_COUNT=4
HUISHI_MAX_ACTIVE_GENERATION_TASKS_PER_USER=2
HUISHI_MAX_REFERENCE_IMAGE_BYTES=5M
HUISHI_MAX_CONTENT_LENGTH=32M
```

如果上线后访问稳定、CPU/内存/错误率都正常，可以将 workers 提升到 5。

### 3.2 可承载量

| 指标 | 保守值 | 乐观值 |
|---|---:|---:|
| 同时生图任务 | 3 | 5 |
| 理论日生成量 | 4,320 张 | 7,200 张 |
| 稳妥日生成量 | 1,000-2,000 张 | 2,000-3,000 张 |
| 可支撑 DAU，重度用户 | 30-100 | 70-150 |
| 可支撑 DAU，普通用户 | 100-300 | 200-500 |
| 可支撑 DAU，轻度用户 | 300-800 | 600-1,500 |

### 3.3 当前瓶颈

当前配置的主要瓶颈：

1. SQLite 写锁：同时写入任务、记录、积分流水时容易阻塞。
2. 本地图片存储：图片越多，服务器磁盘和备份压力越大。
3. 进程内线程池：服务器重启时队列能力弱，无法跨机器扩容。
4. Flask 开发服务器不适合生产，正式上线应使用 Nginx + Gunicorn/Waitress。
5. 图片下载占用应用服务器带宽，建议迁移 OSS/CDN。

## 4. 升级方案与预算

### 4.1 阶段一：当前内测版

适用场景：

- 产品内测。
- 小范围用户试用。
- 每日生成量 1,000-3,000 张。
- DAU 100-800。

配置建议：

| 项目 | 配置 |
|---|---|
| 应用服务器 | 阿里云 2核2G / 200M |
| 数据库 | SQLite |
| 图片存储 | 本地存储，可短期使用 |
| 生图 workers | 3-5 |
| 单用户活跃任务上限 | 2 |

预算：

| 成本项 | 月预算 |
|---|---:|
| 服务器 | 50-150 元 |
| 域名折算 | 5-10 元 |
| 邮件服务 | 0-20 元 |
| 图片存储 | 本地盘，暂不单独计 |
| 固定成本合计 | 55-180 元/月 |

建议：可以先用当前机器验证业务，不建议马上大幅升级。

### 4.2 阶段二：小规模商用版

适用场景：

- 开始收费。
- 日生成量 5,000-10,000 张。
- DAU 500-3,000。
- 希望明显降低用户排队时间。

配置建议：

| 项目 | 配置 |
|---|---|
| 应用服务器 | 4核8G |
| 数据库 | SQLite 可短期继续使用，但需准备迁移 |
| 图片存储 | 阿里云 OSS 或兼容对象存储 |
| 生图 workers | 8-15 |
| 单用户活跃任务上限 | 2-3 |
| 静态资源 | Nginx 缓存或 CDN |

预算：

| 成本项 | 月预算 |
|---|---:|
| 应用服务器 | 200-500 元 |
| OSS 存储 | 20-100 元，取决于图片量 |
| OSS/CDN 流量 | 50-300 元，取决于访问与下载 |
| 邮件服务 | 0-50 元 |
| 备份/监控 | 0-100 元 |
| 固定成本合计 | 270-1,050 元/月 |

预计能力：

| 指标 | 估算 |
|---|---:|
| 同时生图任务 | 8-15 |
| 稳妥日生成量 | 5,000-10,000 张 |
| 普通用户 DAU | 500-1,000 |
| 轻度用户 DAU | 1,500-3,000 |

建议：这是第一阶段最推荐升级档。性价比高，能明显改善排队。

## 5. 业务变量成本

服务器只是固定成本，真正的大头是生图 API。

已知成本：

```text
生图 API：0.05 元/张
Prompt 优化：约 0.002-0.006 元/次
```

若每张图都调用 prompt 优化，则单张变量成本约：

```text
0.052-0.056 元/张
```

月成本估算：

| 日生成量 | 月生成量 | 生图 API 成本 | Prompt 成本 | 变量成本合计 |
|---:|---:|---:|---:|---:|
| 1,000 张 | 30,000 张 | 1,500 元 | 60-180 元 | 1,560-1,680 元 |
| 3,000 张 | 90,000 张 | 4,500 元 | 180-540 元 | 4,680-5,040 元 |
| 10,000 张 | 300,000 张 | 15,000 元 | 600-1,800 元 | 15,600-16,800 元 |
| 30,000 张 | 900,000 张 | 45,000 元 | 1,800-5,400 元 | 46,800-50,400 元 |
| 100,000 张 | 3,000,000 张 | 150,000 元 | 6,000-18,000 元 | 156,000-168,000 元 |

结论：服务器升级预算通常不是最大成本，生图 API 费用才是主要成本项。

## 6. 存储增长估算

按平均每张图片 2MB 估算：

| 日生成量 | 每日新增存储 | 每月新增存储 |
|---:|---:|---:|
| 1,000 张 | 约 2GB | 约 60GB |
| 3,000 张 | 约 6GB | 约 180GB |
| 5,000 张 | 约 10GB | 约 300GB |
| 10,000 张 | 约 20GB | 约 600GB |
| 30,000 张 | 约 59GB | 约 1.8TB |
| 50,000 张 | 约 98GB | 约 2.9TB |
| 100,000 张 | 约 195GB | 约 5.9TB |

建议：

- 日生成量小于 1,000 张：可以短期本地存储，但要备份和清理。
- 日生成量 1,000-3,000 张：建议尽快迁移 OSS。
- 日生成量超过 10,000 张：必须使用 OSS + CDN，否则本地磁盘、备份和带宽都会成为风险。

| 分辨率 | 积分/张 |
|---|---:|
| 1K | 2 点 |
| 2K | 2 点 |
| 4K | 4 点 |

当前套餐折算每点收入约 0.075-0.099 元。对应单张收入：

| 分辨率 | 单张收入 | 单张变量成本 | 单张毛利 |
|---|---:|---:|---:|
| 1K/2K | 0.15-0.20 元 | 0.052-0.056 元 | 0.09-0.15 元 |
| 4K | 0.30-0.40 元 | 0.052-0.056 元 | 0.24-0.35 元 |

在现有 API 成本下，当前定价可以覆盖成本。但需要控制：

- 大量 4K 图片带来的存储与流量增长。

## 8. 推荐升级触发条件

### 继续使用当前 2核2G

满足以下条件时可以继续：

- 日生成量小于 3,000 张。
- 同时等待生成用户小于 50。
- 没有频繁 database is locked。
- 磁盘增长可控。
- 用户能接受 1-5 分钟等待。

### 升级到 4核8G

触发条件：

- 日生成量稳定超过 3,000 张。
- 高峰同时等待生成用户超过 50。
- 用户反馈排队等待明显。
- 计划正式收费。

同时必须做：

- 图片迁移 OSS。
- 生产部署使用 Nginx + WSGI。
- 保持单用户任务上限。

### 升级到 8核16G + RDS/Redis

触发条件：

- 日生成量超过 10,000 张。
- 同时生图希望超过 15。
- DAU 超过 2,000。
- SQLite 出现锁等待或后台查询变慢。

同时必须做：

- 数据库迁移 RDS。
- 队列迁移 Redis/RQ/Celery。
- 图片分发走 CDN。

### 进入多机扩展

触发条件：

- 日生成量超过 30,000-50,000 张。
- 单台机器 worker 不足。
- 需要高可用和故障隔离。

建议：

- Web 服务和 worker 服务拆分。
- 多台 worker 横向扩容。
- 所有图片统一走 OSS。
- 数据库和 Redis 托管化。

## 9. 最终建议

建议采用分阶段预算，而不是一次性购买大配置：

1. 当前阶段继续使用 2核2G，workers 设置 3-5，验证真实使用量。
2. 正式收费前升级到 4核8G，并迁移 OSS。
3. 日生成超过 10,000 张后，升级到 8核16G，同时引入 RDS + Redis。
4. 日生成超过 30,000 张后，拆分 Web 与 worker，进入多机扩容。

短期推荐预算：

| 阶段 | 推荐预算 |
|---|---:|
| 内测验证 | 200 元/月以内，不含 API 成本 |
| 小规模商用 | 1,000 元/月以内，不含 API 成本 |
| 增长期 | 2,000-6,000 元/月，不含 API 成本 |

需要特别说明：如果日生成量达到 10,000 张，生图 API 月成本约 15,000 元，远高于服务器成本。因此预算汇报时应将“服务器固定成本”和“生图 API 变量成本”分开审批。

## 10. 价格说明

本报告服务器、RDS、Redis、OSS、CDN 价格为预算区间估算。实际采购价格受以下因素影响：

- 阿里云地域。
- 包年包月或按量付费。
- 活动折扣。
- 带宽计费方式。
- OSS/CDN 实际流量。
- 数据库高可用等级。

最终采购前应以阿里云控制台报价为准。
